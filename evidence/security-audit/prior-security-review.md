# ApplyPilot security review

This review covers the current email, calendar, web-search and to-do assistant. It does not claim production resistance to every prompt injection. Synthetic data and dedicated test accounts remain mandatory.

| Threat                                                             | Enforcement and evidence                                                                                                                                                                                                                              | Remaining limitation                                                                                                                                                    |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Untrusted email/web text instructs a tool to send or disclose data | Email content is marked untrusted. Sending requires authenticated human approval of exact content, bounded recipient policy and durable outbox state. Tests reject changed, expired, unauthorized and non-allowlisted sends with zero provider calls. | Text-pattern injection detection is incomplete; the deterministic action boundary is the primary defense.                                                               |
| Impersonated Telegram user changes tasks or memory                 | Sender allowlist plus command-context authentication in `telegram-auth.ts`; mutation commands are not model-facing tools. Tests reject untrusted actors and preserve revisions.                                                                       | Compromise of the allowed Telegram account remains a risk.                                                                                                              |
| Private tasks fall back to a cloud model                           | Private workspace defaults to local Gemma, model hook clears fallbacks, session taint persists, unavailable local service holds private tasks. Route metadata excludes raw prompts.                                                                   | Fresh deployed outage evidence must be distinguished from earlier local-Gateway evidence; `g9-live-routing-outage.json` is historical and not a new-image cloud test.   |
| Credential or personal-data leakage through logs                   | Secret Manager runtime credentials, encrypted native-state archives, metadata-only operation samples, no prompt/email/fact bodies in monitoring. Root secret scan passed in `readiness-tls-fix-verify.txt`.                                           | Native framework state can contain sensitive material and must remain private/encrypted. Secret scanning cannot identify every possible secret.                         |
| Corrupt or malicious persistence snapshot                          | Immutable GCS writes, digest/readback verification, authenticated encryption for native state, database integrity checks before restore, traversal and symlink rejection, serialized checkpoints.                                                     | A compromised runtime identity can write new objects. Restore validation is not a defense against an attacker who also obtains encryption keys.                         |
| Process escape or excessive permissions                            | Runtime UID 1000, no effective capabilities, no-new-privileges, root-owned source, restricted plugin/tool inventory, dedicated cloud service account. Startup verifies isolation before declaring ready.                                              | OpenClaw and dependencies remain a substantial trusted computing base. Dependency vulnerabilities remain open; a clean framework audit is not a clean dependency audit. |
| Unauthorized Gateway access                                        | Private Tailscale route plus Gateway token authentication; Tailscale identity alone does not bypass token auth. HTTPS certificate issuance is being verified in current readiness evidence.                                                           | Grader identities and private access handoff must be checked separately; testing from the student's laptop is not proof a grader has joined the tailnet.                |
| Duplicate notification or ambiguous email delivery                 | Durable deduplication/cursors; ambiguous send state held instead of retrying blindly. Live repeated deadline polling returned empty output after one delivered notification.                                                                          | Alert reservation favors duplicate prevention; an uncertain delivery can need manual reconciliation.                                                                    |
| Laptop sleep, cloud outage or lost credentials                     | Minute-scale independent monitoring sinks, explicit model availability state, durable snapshots and restart restoration. Local inference requires powered, awake, connected laptop.                                                                   | Monitoring does not guarantee uptime or provide local inference when hardware is offline. Gaps and missed jobs must be reported.                                        |

Current local verification: 93 tests across 21 files, formatting, linting, type checking and credential-pattern scanning passed (`evidence/readiness-tls-fix-verify.txt`). These tests include provider doubles and are not blanket live-provider evidence.

Latest completed framework deep audit before the TLS correction was on image `0f8fd3f2cc347cc3530181311673be2b645183162c5ea49ad0790ca4b0458089`: zero critical, zero warnings, two informational findings on rerun (`evidence/advanced-security-final.json`). The startup-time probe timeout is retained. A fresh audit of the final image remains required before formal readiness is marked complete.

The HTTPS issue was diagnosed from actual `no TailscaleVarRoot` errors. The correction supplies a private state directory and encrypts the certificate cache in the native vault. Regression tests cover cache recovery, restricted key-file permissions and symlink/traversal rejection. Certificate issuance and authenticated access must be verified separately; enabling Serve alone is not sufficient.

Resource selection: the instance currently uses 2 vCPU and 4 GiB for the two-agent OpenClaw runtime, database startup work and monitoring. This is a headroom choice, not an assignment minimum or measured minimum. The assignment recommends beginning smaller and documenting increases; record actual utilization/cost in the operational report before claiming optimal sizing.
